# 차곡ERP — 4일 차 주요 사용자 시나리오 및 수용 조건

> 버전: v0.2 / 2026-11-17  
> 상태: P0 기준 시나리오 초안. 사용자 역할·문서 상태·문구는 후속 화면/권한 설계에서 확정.  
> 참고: PRD S1~S3, FUNCTIONAL-SPEC, 2일 차 ERP-WORKFLOW·BR-001~023, [사이트맵](07-SITEMAP-SCREEN-LIST.md).

## 작성 기준

- **Precondition(사전 조건) → 사용자의 행동 → 시스템 결과 → 실패 경로 → 완료 판정** 형식.
- AI Studio의 Mock 화면에서는 화면 이동을 검증하고, **최종 완료 판정은 Spring Boot API·DB를 연결한 통합 테스트**에서 한다.
- 명세된 P0 범위 밖의 실제 주문 전송·결제·입고 취소는 시나리오에 넣지 않는다.
- 예시 수량은 **하나의 기준단위 EA**를 사용하는 시연용 품목에 한정한다. P0는 품목별 기준단위, Decimal 수량, KRW 단일 통화, 단위 환산 제외 방향으로 한다. 세부 정밀도·반올림은 DB/API 설계에 남아 있다.

## US-01 — 일반 구매요청 → 승인 → 내부 PO → 입고 (대표 성공 경로)

- **대상:** 요청자, 승인자, 구매 담당자, 창고 담당자.
- **선행:** 활성 품목 M-100(기준단위 EA), 공급업체 S-10, 창고 W-1/저장위치 L-1, 역할별 테스트 계정이 존재한다.
- **연결:** `PR-01/02`, `APR-01`, `PO-01~03`, `GR-01`, `ST-01`, `SEC-01/02`, `AUD-01`.
- **화면:** `SCR-PR-001/002/003 → SCR-APR-001 → SCR-PO-001/002 → SCR-GR-001/002 → SCR-STK-001/002`.

| 순서 | 사용자 행동 | 기대 시스템 동작 |
|---|---|---|
| 1 | 요청자가 M-100, 100 EA로 PR 작성·임시 저장 | 본인 소유 `DRAFT` 및 품목 항목 생성 |
| 2 | PR 제출 | 필수값/버전/권한 검증 후 `SUBMITTED` |
| 3 | 승인자가 승인 | `APPROVED` 전이, 이력 보존 |
| 4 | 구매 담당자가 S-10, 단가·발주 수량을 입력해 PO 생성 | 승인된 PR 품목만 참조해 내부 `OPEN` PO 생성; **PR 품목별 미발주 잔량** 안에서 추가 PO 생성 가능 |
| 5 | PO 연락처·내역 조회/인쇄 | 연락처·예상 금액·품목/수량 표시, **실제 주문 발송 없음** |
| 6 | 창고 담당자가 100 EA 수동 입고 | 단일 트랜잭션으로 PO 누적/GR/원장/현재고 반영 |
| 7 | PO 상세·원장/재고 확인 | `RECEIVED`, PO 잔량 0, 이동 1건, 시연용 현재고 +100 |

**예외:** 미승인 PR→PO 요청 거부, 비활성 공급업체 거부, 승인자 외 사용자의 승인 거부, 다른 창고 소속 저장위치 지정 거부.  
**완료 판정:** 화면뿐 아니라 PO/GR/StockMovement/StockBalance와 이력을 DB에서 검증한다. **PO 생성=실제 구매 완료로 표시하지 않는다.**

### US-01A — 한 PR을 여러 공급업체/PO로 분할 발주 (D-01 확정 방향)

- 선행: 승인된 PR-10의 품목 A(100 EA), 공급업체 S-10/S-20 활성. PR 헤더는 **전체 `APPROVED`** 상태이고 품목별 승인 상태는 없다.
- 구매 담당자: PO-10(S-10, A 60 EA)을 생성한다. PR 품목의 미발주 잔량은 40 EA.
- 구매 담당자: PO-11(S-20, A 40 EA)을 생성한다. PR 품목의 미발주 잔량은 0 EA.
- 추가로 PO-12(A 1 EA)를 만들면 거부한다. 새로운 요청키로 동시에 60+60을 만들더라도 둘 다 성공할 수 없다.
- 각 PO는 창고 담당자가 따로 입고한다. **PO의 미입고 잔량은 각 PO 기준**으로 계산하고, PR의 미발주 잔량과 섞지 않는다.
- 동일 PO 생성 요청키·같은 본문 재시도는 기존 PO만 반환하며 새 PO를 만들지 않는다.

**완료 판정:** PR 품목의 유효 PO 발주 합계는 승인 수량 이내, PO별 공급업체는 한 곳, 잘못된 발주 생성 요청은 DB에 부분 변경이 없다.

## US-02 — 반려 → 수정·재제출 → 승인 (정상 분기)

- **선행:** 요청자가 유효한 PR을 제출, 승인자는 별도 계정.
- **화면:** `SCR-PR-003 ↔ SCR-APR-001 ↔ SCR-PR-002`.
- **절차:** 승인자 반려 사유 작성 → PR `REJECTED` 및 사유/이력 저장 → 요청자가 사유 확인·재작업 시작 → `DRAFT`에서 수정 → 재제출 → 승인.
- **예외:** 반려 사유 누락, `APPROVED` PR 수정 시도, 요청자 아닌 사용자의 재작업, 승인과 반려 동시 경쟁.
- **완료 판정:** 이전 반려 사유/승인 이력이 보존되며, 동일 PR에 대해 허용된 상태 전이만 발생한다.
- **연결:** `PR-02`, `APR-01`, `AUD-01`, BR-002~004.

## US-03 — PO 100 EA에 대해 60 EA + 40 EA 부분 입고

- **선행:** 승인 PR로 생성된 PO의 한 품목 수량 100 EA, 누적 입고 0, 시연용 초기 재고 0.
- **화면:** `SCR-PO-002 → SCR-GR-001 → SCR-GR-002 / SCR-STK-001/002`.

| 요청 | 예상 PO 누적 | 예상 잔량 | 원장 | 현재고 변화 | PO 상태 |
|---|---:|---:|---|---:|---|
| 첫 입고 60 EA | 60 | 40 | GR1에 연결된 입고 +60 | +60 | PARTIALLY_RECEIVED |
| 두 번째 입고 40 EA | 100 | 0 | GR2에 연결된 입고 +40 | +100 누적 | RECEIVED |
| 세 번째 1 EA 시도 | 100 | 0 | 변화 없음 | 변화 없음 | RECEIVED |

**경쟁/멱등성 확장 검증(같은 시나리오):** 서로 다른 요청 60+60을 동시에 보내도 발주량 초과 불가. 같은 요청키·같은 요청 재전송은 중복 GR을 생성하지 않음. 같은 키·다른 내용은 충돌 처리(계약 제안).  
**실패:** PO 누적 반영 후 재고 기록에서 실패하면 모든 DB 변경을 롤백.  
**연결:** `PO-03`, `GR-01/02`, `ST-01`, BR-006~012, BR-020~022.

## US-04 — Agent 자연어 조회·규정 근거·PR 초안 생성/수정

- **대상:** PR 작성 권한이 있는 로그인 사용자.
- **화면:** `SCR-AI-001 → SCR-PR-003`.
- **선행:** 테스트용 구매 규정(시행일/버전/출처), 품목/재고/공급업체/구매 이력 Mock 아닌 ERP 조회 경로를 준비.

1. 사용자가 품목·재고·공급업체를 조회하고 구매 규정을 질문한다.
2. Agent가 **권한 있는 ERP 조회 Tool**과 근거 검색을 수행하여 출처·시행일을 함께 제시한다.
3. 품목·수량/기준 조건이 불명확하면 임의 확정하지 않고 **재질문**한다.
4. 입력값이 충분하고 PR 저장 요청이 유효하면 공통 PR 서비스로 `DRAFT`를 생성하고 `draftId`, `version`, item ID를 저장한다.
5. 사용자에게 표시한 항목 목록과 DB의 실제 PR 항목 ID를 연결한다.
6. “두 번째 품목 빼고 첫 번째 품목 수량 20개로 바꿔줘” 요청 시 **정확한 itemId와 version**으로 수정한다.
7. 화면에서 수정된 PR과 새 버전이 보이고, PR 상세에서 확인된다.

**예외:** “두 번째”가 모호하면 되묻는다. 다른 사용자의 PR, 최신 버전이 아닌 초안, 비활성 품목이면 거부한다. 승인·PO·GR·결제 실행 Tool은 제공하지 않는다.  
**완료 판정:** 조회/근거/재질문/초안 생성/후속 수정이 실제 ERP 데이터와 일치하고, 실패 시 DB에 임의 변경이 없다.  
**연결:** `AG-01~07`, `PR-01`, `SEC-01/02`.

## US-05 — Assistant에서 Excel·텍스트 PDF 업로드 → 품목 검토 → PR

- **대상:** PR 작성 권한이 있는 로그인 사용자.
- **화면:** `SCR-AI-001` 내부 `SCR-AI-002` 문서 검토 패널 → `SCR-PR-003`.
- **선행:** 유효한 Excel 및 **텍스트 추출 가능한** PDF 샘플, 원본 Material 및 검색 색인, 규칙 기반 약어 사전.

1. 사용자가 Assistant 대화창에서 파일을 첨부하고 분석을 요청한다.
2. B의 문서 파이프라인이 파싱·필드 구조화를 수행하고 품목명/규격/단위/수량과 추출 문제를 표로 제공한다.
3. 품목 코드·정규화·유사어를 우선 적용하고, 불명확한 행은 Elasticsearch BM25 후보를 제시한다.
4. 필요한 후보에 한정해 LLM 비교를 수행하되 확신이 없으면 미확정으로 둔다.
5. 사용자가 잘못된 항목을 수정하고 정확한 ERP `materialId`를 선택한다.
6. **모든 필수 행이 검증된 후**, 확인된 자료만 공통 PR DRAFT 서비스에 전달한다.
7. 저장된 DRAFT ID와 품목·수량을 다시 보여준다.

**예외:** 손상/빈 파일, 지원되지 않는 이미지 PDF, 파일 제한 초과, 단위 불일치, 미선택 품목, ES 장애, LLM 장애, 검토 이후 원본 품목 비활성화, 저장 중복.  
**완료 판정:** 원문 해석 결과와 저장된 PR 품목이 연결되며, 검토되지 않은 후보가 PR에 자동 반영되지 않는다.  
**연결:** `DOC-01~05`, `MATCH-01~03`, `PR-01`, `UI-03`.

## US-06 — 권한·경합·입력 실패 경로(교차 검증)

| 시나리오 | 조작 | 기대 동작 |
|---|---|---|
| 인증 없음 | 보호 메뉴/API 접근 | 로그인 요구/401, 도메인 데이터 미노출 |
| 승인 권한 없음 | 제출 PR 승인 요청 | 거부/403, 상태·이력 무변경 |
| 타인 PR | `DRAFT` 수정 요청 | 거부/403, 버전 무변경 |
| 버전 충돌 | 동일 초안을 두 사용자/탭에서 갱신 | 오래된 버전은 충돌, 임의 덮어쓰기 금지 |
| GR 중복 키 | 성공한 요청 재전송 | 이전 GR 결과를 보여주고 수량 중복 반영 없음(제안) |
| GR 잔량 초과 | 잔량 40에 41 요청 | 거부, PO/GR/원장/현재고 무변경 |
| Document AI 모호 | 유사 품목 두 개 규격 불명 | 후보 비교 제시, 사용자 명시 선택 전 저장 금지 |
| RAG 근거 부재 | 규정 답변 요청 | 출처 없는 승인 규정을 만들어내지 않음 |

**화면 상태 확인:** 모든 주요 CRUD/조회는 로딩·빈 데이터·유효성 오류·권한 오류·버전 충돌을 분리하여 표시한다. 저장 버튼 반복 클릭은 중복 비즈니스 기록을 생성하지 않도록 백엔드 정책과 연결한다.

## 7. 시나리오 → 화면·기능·테스트 추적

| 시나리오 | 화면 | 주요 기능 | 테스트 초안 |
|---|---|---|---|
| US-01 일반 구매·분할 발주 | PR/승인/PO/GR/재고 | PR/PO/GR/ST/SEC | E2E-01 (+ 분할 발주 E2E-01A) |
| US-02 반려·재제출 | PR 상세·승인함 | PR-02, APR-01, AUD-01 | E2E-02 |
| US-03 부분 입고 | PO 상세·GR·원장 | PO-03, GR-01/02, ST-01 | E2E-03 |
| US-04 대화 Agent | AI Assistant·PR 상세 | AG-01~07, PR-01 | E2E-04 |
