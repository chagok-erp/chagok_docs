# 차곡ERP PRD — 제품 요구사항 정의서

> **문서 버전:** v0.3 · 2026-11-17 · 최신 피드백 반영  
> **기준:** [차곡ERP 통합 기획서 v3.3](차곡ERP_통합기획서_v3.3.md)  
> **개발:** 2명 / 최대 20주 / PC 중심 반응형 웹  
> **상태:** 팀 공유용 개정안. 우선순위와 담당 범위는 사용자 대화에서 확인된 결정을 반영하였으나, 최종 회의·서명은 별도이다.

## 1. 제품 정의

**차곡ERP는 SAP S/4HANA의 공개 구매·재고 프로세스와 API 명세를 참고하여 자체 개발한 구매·재고 ERP에, 대화형 Agent와 구매문서 자동 분석·품목 매칭을 하나의 AI Assistant 사용자 경험으로 연결하는 시스템이다.**

- ERP: Java·Spring Boot, PostgreSQL, 자체 도메인/상태/트랜잭션 구현.
- UI: React·TypeScript 기반 PC 중심 웹.
- AI: ERP 조회·구매 규정 RAG·PR 초안 생성/수정 + 문서 파싱·품목 매칭.
- 검색: PostgreSQL 품목 원본과 분리된 Elasticsearch 파생 인덱스.
- 실제 SAP 설치·연동/ABAP 개발·실거래·대리결제는 제품 범위가 아니다.

## 2. 문제 정의

| 문제 | 사용자 불편 | 해결 방향 |
|---|---|---|
| PR·PO·GR 단절 | 요청·발주·입고의 진행 상태와 잔량 확인 어려움 | 동일 업무 식별자와 상태 전이로 문서 연결 |
| 구매문서 수작업 | 엑셀·PDF 품목을 ERP 규격과 매번 대조 | 파싱·매칭·수정·검토 후 공통 PR 초안 저장 |
| 분산된 조회·규정 | 재고·공급업체·구매 규정을 여러 화면에서 찾음 | Agent 조회 Tool과 출처 기반 RAG |
| 정합성 위험 | 중복 입고·동시 요청·AI 잘못된 실행 | 서버 업무 검증·트랜잭션·멱등성·권한 통제 |

참고 사례인 김동년 포트폴리오의 문서 추출·사용자 검증·ERP 입력 자동화 원칙과 `Rule-Based → 필요 시 AI` 전략을 제품 설계에 참고하되, 해당 사례의 정확도·절감액을 차곡ERP 성과로 인용하지 않는다.

## 3. 제품 목표

### 기능 목표

1. **ERP만으로 완결:** 품목·공급업체·창고 → PR → PR 전체 승인·반려 → 승인 수량 안에서 여러 내부 PO(분할 발주) → 수동 GR·부분 입고 → 재고 원장·현재고.
2. **대화 기반 업무 단축:** 허용된 조회와 규정 검색을 바탕으로 PR DRAFT를 생성·수정; 다중 턴 참조 및 재질문 지원.
3. **문서 기반 입력 단축:** 제한된 형식의 Excel·텍스트 PDF를 구조화하고 ERP 품목과 매칭; 사용자가 검토한 값만 PR로 저장.
4. **업무 실행 안전성:** 권한·문서 소유권·버전·상태·수량을 Spring Boot 서버에서 최종 검증.
5. **측정 가능한 결과:** ERP 정합성 테스트와 두 AI 경로의 업무 성공·실패·검색·비용·지연을 기록.

### 비목표

이번 개발은 구매·재고 ERP와 AI 자동화의 **작동·검증**에 집중한다. 실제 공급업체 주문 전송, 금융 결제, 전체 회계·정산, 송장 검증, 다단계 결재, MES·설비 제어·실시간 생산 모니터링은 목표가 아니다.

## 4. 대상 사용자

| 사용자 | 달성하려는 일 | 대표 권한 |
|---|---|---|
| 구매 요청자 | 필요한 품목의 PR 작성·제출 | 본인 PR 초안 생성·수정·조회 |
| 구매 담당자 | 승인된 PR의 내부 PO 생성·관리 | PO 생성·조회·발주 금액 확인 |
| 승인자 | PR의 승인·반려 | 승인 권한 대상 문서만 처리 |
| 창고 담당자 | PO 기준 입고·재고 처리 | GR 등록·재고/원장 확인 |
| 관리자 | 공통 사용자·역할·기준정보 관리 | 관리 업무 범위에서만 변경 |

하나의 사용자가 복수 역할을 가질 수 있는지는 상세 권한 설계에서 결정한다. 역할만으로 충분하지 않은 경우 문서 소유권과 상태도 확인한다.

## 5. 사용자 시나리오 및 수용 조건

### S1 — 수동 구매에서 입고까지

1. 요청자가 PR 초안을 작성해 제출한다.
2. 승인자가 **PR 헤더 전체에 대해** 일괄 승인 또는 반려를 처리한다. 품목별 선택 승인/반려는 하지 않는다.
3. 구매 담당자가 승인된 PR의 품목별 **발주 가능 잔량**을 확인한 후, 하나 이상의 내부 PO로 나누어 발주한다. PO마다 공급업체 1곳을 선택하고 연락처·품목·수량·단가·총액을 확인한다.
4. 발주서 상세 화면을 조회하거나 브라우저 인쇄한다. **실제 주문을 전송하지 않는다.**
5. 창고 담당자는 테스트용 납품 상황을 가정하고 수동 GR을 등록한다.
6. PO 누적 입고량, GR 문서, StockMovement, StockBalance가 함께 반영된다.

**수용 조건:** PR 품목 100개를 PO-A 60개·PO-B 40개로 분할 발주 가능하되 추가 PO 1개는 거부한다. 두 PO는 각각 독립적으로 입고할 수 있다. 또한 PO 100개에 60개·40개 GR이 가능하며 초과·중복 입고 및 중간 실패의 부분 반영이 없어야 한다.

### S2 — 대화형 Assistant의 구매요청 초안 생성·수정

1. 사용자가 “재고 부족 품목과 최근 구매 이력, 공급업체를 확인하고 규정을 검토해 PR 초안을 만들어 줘”라고 요청한다.
2. Agent가 로그인한 사용자의 권한으로 조회 Tool 및 RAG를 수행한다.
3. 근거·식별 정보가 부족하면 답변을 지어내지 않고 재질문한다.
4. ERP PR 서비스의 검증을 통과한 DRAFT를 저장하고 사용자에게 확인 화면을 제공한다.
5. “두 번째 품목 제외, 첫 번째 품목은 20개”라는 후속 요청을 `draftId`, 버전 및 항목 ID를 사용해 처리한다.

**수용 조건:** 업무 상태·권한 위반은 차단하며 AI가 승인·입고·현재고·결제를 직접 변경하지 않는다.

### S3 — 통합 Assistant에서 문서 첨부

1. 사용자는 **동일 Assistant 화면**에서 지정된 Excel 또는 텍스트 PDF를 첨부한다.
2. 문서 처리 모듈이 품목명·규격·단위·수량을 추출·검증한다.
3. 품목 코드·정규화·유사어 규칙으로 먼저 매칭하고, Elasticsearch 후보 검색을 수행한다.
4. 모호한 후보는 필요한 경우에만 LLM으로 비교한다.
5. 사용자가 결과를 **표 형태로 확인·수정·선택**하고 PR 초안 생성을 요청한다.
6. ERP PR 서비스가 원본 품목·수량·권한·상태를 검증해 저장한다.

**수용 조건:** 불확실한 품목을 근거 없이 자동 확정하지 않으며, 업로드된 문서를 AI가 신뢰된 명령으로 해석하지 않는다.

## 6. 제품 범위 및 우선순위

### P0 — 필수 MVP

**ERP** — 품목·공급업체(연락처)·창고·저장위치, PR 초안/제출, PR 헤더 일괄 승인/반려, 내부 PO 분할 생성·조회·간단 인쇄, PO 입고 수량 검증, 수동·부분 GR, 원장·현재고, 기본 업무 이력·서버 권한, 동시·중복 작업 방지.

**대화형 AI** — ERP 조회 Tool, 구매 규정 RAG/출처 표시, 기본 문맥/재질문, PR DRAFT 생성·수정, 권한·버전·오류 처리, 기본 평가.

**문서 AI** — Excel·텍스트 PDF 지원, 필드 추출·검증, 품목 코드/유사어 규칙·Elasticsearch BM25 검색, 모호한 경우 LLM 보조, 검토·수정 후 공통 PR 초안 서비스 연동, 기본 평가.

**공통** — **하나의 AI Assistant UI**, Spring Security 기반 인증·인가(구체 방식 미정), 공통 디자인·레이아웃, 기본 통합 테스트, CI/CD·배포·로그/모니터링·PostgreSQL 운영 환경 공동 구축.

### P1 — P0 안정화 후

입고 취소·역거래 고도화, Vector/Hybrid Search 비교 및 매칭 개선, Agent 문맥·오류 복구 고도화, 검색 인덱스 대량 재색인, PO 인쇄용 PDF, 예상 발주 금액 집계(지급액 아님), AI 평가·운영 화면, 반응형 고도화.

### P2 — 확장 후보만 유지

BOM·간소화 MRP·부족 자재 PR 연계, 다단계 결재, 송장 검증 및 **가상 지급 상태 기록**(실자금 이동 없음), OCR/스캔 PDF, Multi-Agent, 모바일 앱/PWA, 실제 SAP 연동, 생산·회계 확장.

**P2는 5개월 완료 범위가 아니다.** 특히 다단계 결재·송장 검증·모의 지급은 이번 일정에 구현을 약속하지 않는다.

**확정한 업무 범위:** `D-01=PR 1:N PO 분할 발주`, `D-02=PR 헤더 전체 일괄 승인`. 품목별 승인·승인 수량 조정은 제외한다. 분할 발주는 PO 간 수량 배분을 허용하는 것이며 PO 취소·재배분은 P0에서 제외한다.

### 명시적 제외

- 실제 공급업체 주문 발송/EDI·자동 발주 전송, 실구매·실결제·대리결제·PG 연동·자금 이체·정산.
- 다단계 결재, 송장 검증의 본격 구현 및 지급 처리.
- MES 전체, 생산작업지시·실적·설비 제어·실시간 생산 데이터 수집.
- SAP S/4HANA 서버·ABAP 개발, 인사·급여 등 전사 ERP 구축, Kubernetes 필수 도입.

세부 기능·기능 ID·완료 조건은 [MVP 기능 범위표](02-MVP-SCOPE.md)에서 정의한다.

## 7. 핵심 업무 정책

| 정책 | 요구사항 |
|---|---|
| PO는 내부 문서 | 승인된 PR에서 **1:N PO 분할 발주**, 각 PO는 공급업체 1곳, PR 품목별 합계≤승인 수량; 외부 발주·결제 미수행 |
| PO 수량 | 원발주 수량 보존, 누적 입고량 별도 관리 |

| PR 발주 가능 잔량 | `PR 품목 승인 수량 − 유효 PO 품목들의 발주량 합계`. 같은 품목의 동시 PO 생성·동일 요청 재시도는 초과 발주와 중복 생성을 방지 |
| 입고 | PO 잔량 초과 금지, 중복 GR 미반영, PO·GR·원장·현재고 원자성 |
| PR 초안 | UI·Agent·Document AI 모두 **하나의 ERP PR 저장 서비스** 사용 |
| 품목 기준정보 | PostgreSQL이 원본, Elasticsearch는 검색·추천용 파생 데이터 |
| 문서 확인 | 정확한 품목 ID·단위·수량은 사용자 검토 후 ERP 서버 재검증 |
| AI 실행 | 허용 Tool만 호출, 최종 승인은 사람이 수행, 오류·근거 부족 시 유보 |
| 사용자 권한 | B의 공통 인증 인프라 + 각 모듈 소유자의 세부 업무 권한 검사 |

## 8. 품질 및 비기능 요구사항

1. **정합성:** PO 누적 입고량, GR, StockMovement, StockBalance를 같은 DB 트랜잭션에서 처리.
2. **경합·멱등성:** 동일 요청 ID 중복 실행과 동시에 들어오는 초과 GR을 차단; 테스트 결과로 증명.
3. **보안:** 역할·소유권·문서 상태 검증, LLM 입력의 프롬프트 인젝션 통제, API Key 비공개, 최소 권한.
4. **추적성:** 주요 문서 상태 변경의 처리자·시각, AI Tool 실행 결과·오류를 비밀정보 없이 기록.
5. **AI 품질:** 규정 출처/시행일, 잘못된 품목 자동 확정 최소화, 추출·검색·Tool 호출 평가.
6. **운영:** CI/CD, 공통 로그·모니터링, 재현 가능한 배포, PostgreSQL 백업·복구 절차.
7. **측정:** 성능·정확도·토큰 비용 목표 숫자는 평가 데이터와 기준치를 확보한 뒤 합의한다.

## 10. 담당과 공동 업무

- **A:** 품목·공급업체, PR·승인·PO, PO 잔량 서비스, 대화형 Agent·RAG, Agent·구매 화면, 공통 UI/UX 디자인.
- **B:** 창고·GR·재고, Document AI·Elasticsearch·품목 매칭, 문서 검토·재고 화면, **인증·사용자·공통 권한 인프라**.
- **공동:** 전체 ERD/API·PO↔GR 계약, 종단 간 테스트, **CI/CD·배포 인프라·공통 로깅/모니터링·PostgreSQL 공통 운영/백업/복구**.

세부 소유권은 [역할 분담서](03-ROLE-AGREEMENT.md) 참고.

## 11. 성공·완료 기준

| 항목 | 완료 판정 |
|---|---|
| ERP 종단 간 | 권한 있는 사용자로 PR 제출·승인·PO 생성·부분 GR·재고 반영 시연 |
| ERP 동시성 | 중복·초과 GR 차단 및 전체 롤백의 자동화 테스트 |
| 대화형 Agent | 조회·RAG·PR 초안 생성·후속 수정·재질문·권한 차단 시연 |
| 문서 AI | Excel/텍스트 PDF → 추출 → 매칭 → 사용자 검토 → PR DRAFT 시연 |
| 평가 | 통합/예외 테스트 결과 및 AI 품질·지연·비용 측정 자료 |
| 배포 | 공동 운영 환경에서 위 시나리오 반복 시연 가능 |

## 12. 작업 착수 및 문서 계획

- **1일 차:** PRD, P0/P1/P2, A/B 및 공동 책임 확정.
- **2일 차:** SAP 자료를 참고한 PR → PO → GR 업무 상태·예외 흐름 초안.
- **3일 차:** `FUNCTIONAL-SPEC.md`에 기능 ID, 입력, 검증, 예외, 수용 기준 기록.
- **4일 차:** 사이트맵·주요 화면 흐름·AI Studio 대표 화면 프로토타입.
- **5일 차:** PO↔GR, Material↔검색, Document AI↔PR, Agent↔권한 계약 검토.
- **2주 차 이후:** ERD/DB 사전, OpenAPI, 화면 명세, AI 상세 설계 및 Rust PoC를 필요한 순서로 병행.

문서 작성 때문에 첫 구현을 지연하지 않는다. 업무 계약을 먼저 합의한 범위부터 개발하고 명세·테스트를 함께 갱신한다.
