# 차곡ERP — MVP 기능 범위·우선순위·완료 기준

> **버전:** v0.3 · 2026-11-17  
> **기준:** [기획서 v3.3](../차곡ERP_통합기획서_v3.3.md) · [PRD v0.3](01-PRD.md) · [역할 분담](03-ROLE-AGREEMENT.md)  
> **목적:** 개발자 A/B가 **P0 필수 기능**, P1 고도화, P2 확장 후보 및 이번 개발 제외 범위를 동일하게 이해하기 위한 합의 문서.

## 1. 우선순위 정의

- **P0:** 최대 20주 안에 구현·자동화 테스트·실제 배포 시연해야 하는 핵심 기능.
- **P1:** P0가 정상 동작한 후 시간을 배분하는 품질·사용성 고도화.
- **P2:** 장기 확장 후보. 이번 5개월 내 완성을 약속하지 않음.
- **이번 범위 제외:** 기능 추가를 전제로 설계하거나 작업 일정을 잡지 않음. P2에 남긴 기능도 현 일정에서는 제외.

아래 ID는 **MVP 관리용 임시 기능 ID**다. 세부 `FUNCTIONAL-SPEC.md` 작성 시 정규 ID를 부여한다. P0의 '완료'는 화면만 있는 상태가 아니라 서버 동작, 검증 및 해당 테스트가 있는 상태다.

**B 피드백 수용으로 확장된 P0(2026-11-18):** GR 초안 저장/수정/재개, 명시적 POSTED 확정, 동일 POItem 저장위치별 배분, 동일 PR에 같은 품목의 서로 다른 PRItem 행 허용, 창고·저장위치 물리 삭제 제한/비활성화, 공급업체 연락처 보관만 지원. 공장·GR 취소·재고 이동·실제 발송은 제외.

### ERP P0 수용 테스트

- 승인되지 않은 PR로 PO를 생성할 수 없어야 한다.

- **PR 품목 100 EA**를 공급업체가 서로 다른 PO 60 EA·40 EA로 분할 발주할 수 있으며, 추가 1 EA PO 생성 요청은 거부되어야 한다. 별도 요청키의 경쟁 PO 60+60도 승인 수량 100을 초과해 모두 성공해서는 안 된다.
- 하나의 PR에서 서로 다른 유효 PO 생성은 허용하지만, **같은 요청키로 동일 PO를 중복 생성해서는 안 된다.**
- PO 100개 → GR 60개 → GR 40개 → 누적 입고 100개, 잔량 0, 원장·현재고 일치.
- PO 잔량이 40일 때 추가 50개 입고 요청을 거부해야 한다.
- 동시 60개·60개 입고가 잔량 100개를 초과해 모두 성공해서는 안 된다.
- 동일 요청 ID의 GR 재시도로 수량이 두 번 증가하지 않아야 한다.
- PO 갱신 후 GR/재고 처리에 오류가 나면 전체 롤백되어야 한다.
- 요청자 본인의 PR만 수정할 수 있고, 권한 없는 승인·입고는 거부되어야 한다.
- 내부 PO 생성 시 PG 결제·실제 주문 전송을 호출하지 않아야 한다.

## 3. P0 — 통합 AI Assistant: 대화형 Agent / RAG (A)

| 임시 ID | 기능 | 최소 완료 조건 |
|---|---|---|
| AG-01 | 통합 Assistant 채팅 진입점 | 사용자 대화, 오류·재질문, 상태 표시(파일 입력은 B 모듈과 연결) |
| AG-02 | ERP 조회 Tool | 허용 범위의 품목·재고·공급업체·과거 구매 내역 조회; 실패·권한 오류 노출 |
| AG-03 | 구매 규정 RAG | 검색 근거·출처·시행일 표시, 자료 부족 시 유보 |
| AG-04 | PR DRAFT 생성 | ERP 공통 PR 서비스의 필수값·역할·상태 검증 후 저장 |
| AG-05 | 후속 초안 수정 | `draftId`, 버전, 화면 표시 항목과 실제 항목 ID를 이용해 수정; 모호하면 재질문 |
| AG-06 | 실행 통제·중복 호출 대응 | 승인·PO 확정·GR·재고 직접 변경·결제 Tool 미제공, PR 재시도 시 중복 저장 방지 |
| AG-07 | 기본 품질 평가 | 정상·모호·오류·권한·버전 충돌 케이스에서 Tool 선택·성공·지연·토큰 비용 기록 |

**Agent 시연:** 사용자가 품목·재고·규정을 묻고 PR 초안을 생성한 뒤 “두 번째 품목 제외하고 첫 번째 수량 20”이라고 수정한다. 실제 ERP에서 동일 초안의 버전·수량을 확인한다.

## 4. P0 — 통합 AI Assistant: 문서 처리·품목 매칭 (B)

| 임시 ID | 기능 | 최소 완료 조건 |
|---|---|---|
| DOC-01 | 파일 첨부·파싱 | 합의된 형식의 Excel/텍스트 PDF 업로드와 주요 항목 추출 |
| DOC-02 | 구조화·필드 검증 | 품목명·규격·단위·수량 추출, 누락·오류·단위 불일치 표시 |
| MATCH-01 | **Rule-Based 우선 매칭** | 정확한 품목 코드, 정규화, 소규모 제조 부품 유사어/약어 사전으로 후보 매칭 |
| MATCH-02 | Elasticsearch 후보 검색 | PostgreSQL 품목으로 구성한 색인에서 BM25/키워드 검색, 후보 규격 비교 |
| MATCH-03 | 필요 시 LLM Fallback | 후보가 모호할 때만 구조화된 후보 비교; 애매한 결과 자동 확정하지 않음 |
| DOC-03 | 품목 후보·수량 사용자 검토 | 채팅 화면 내 표·패널에서 사용자 선택·수정·오류 확인 |
| DOC-04 | 공통 PR DRAFT 연동 | 확인된 `materialId`, 수량·단위를 A의 PR 서비스로 전달하고 원본 데이터 재검증 |
| DOC-05 | 기본 평가 | 필드 정확도, Top-1, Recall@5, LLM 호출 수·오확정률·지연·비용 기록 |

**문서 AI 시연:** 구매 품목 목록 Excel/텍스트 PDF 첨부 → 추출 → 규칙/검색/LLM 후보 → 사용자 선택·수정 → ERP에 PR DRAFT 저장.

**P0와 P1 경계:** P0는 **Rule-Based + Elasticsearch BM25 + 필요한 경우 LLM Fallback**을 기본으로 한다. Vector/Hybrid Search 비교·품질 실험의 확대는 P1이다. 초기 P0에 모든 양식·OCR·완전 자동 확정을 요구하지 않는다.

## 7. P2 — 장기 확장 후보(이번 개발 범위 아님)

- BOM 관리·생산 필요 자재 소요량 계산·재고 부족 품목 PR 연계(간소화 MRP).
- 다단계 결재, 송장 검증, **입고·청구 대조 이후 모의 지급 상태 기록**(실제 돈의 이동 없음).
- OCR·이미지/스캔 PDF, Multi-Agent, 모바일 앱/PWA.
- 실제 SAP 시스템 연동, 생산·회계 영역 확장.

**MES 전체 구축은 후보가 아니다.** 작업지시·생산실적·설비제어·현장 데이터 수집은 명시적으로 제외한다. P2의 간소화 MRP도 MES가 아닌 별도의 ERP 확장안이다.

## 9. 최종 데모용 업무 흐름

1. 로그인(서로 다른 역할로 권한 확인).
2. 요청자: 구매 품목 수동 PR 생성·제출.
3. 승인자: 승인 처리 → 구매 담당자: **내부 PO** 생성·연락처/금액 확인·인쇄.
4. 창고 담당자: PO에 대해 60개/40개 부분 GR → 현재고·원장 확인.
5. 통합 Assistant: 품목·재고·규정을 조회하고 PR 초안 생성·후속 수정.
6. 동일 Assistant: Excel/텍스트 PDF 첨부 → 규칙/검색/LLM 후보 → 검토 → PR 초안 저장.
7. 중복·동시 입고 및 권한 오류 테스트 결과와 AI 품질·지연·비용 기록 확인.

## 10. 1일 차 합의 체크리스트

- [ ] AI는 **하나의 Assistant 화면**으로 통합하지만 A/B 내부 책임은 유지한다.
